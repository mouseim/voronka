# Воронка — простой конструктор Telegram-воронок

Статический визуальный редактор для людей без технической подготовки. Воронка собирается по принципу:

```text
добавил сообщение → добавил кнопки → получил выходы → соединил ветки
```

Приложение работает без backend и аккаунта. Проект, настройки будущего бота и снимок статистики переносятся одним читаемым UTF-8 JSON-файлом с расширением `.funnel`.

Важно: редактор не подключён к Telegram и платёжной системе. Сообщения, таймеры, медиа и оплата в предпросмотре только моделируются. Токены и секреты не запрашиваются и не хранятся.

## Запуск

Требуется Node.js 20 или новее.

```bash
npm install
npm run dev
```

Проверка:

```bash
npm test
npm run build
npm run test:e2e
```

Демонстрационный файл: [`public/demo-7-mehanizmov-v2.funnel`](public/demo-7-mehanizmov-v2.funnel).

## Основной интерфейс

В библиотеке осталось 10 типов блоков:

1. Старт.
2. Сообщение.
3. Медиа.
4. Пауза.
5. Тест.
6. Форма.
7. Согласие.
8. Продукт.
9. Внешняя ссылка.
10. Завершение.

Отдельного блока «Выбор» нет. Обычное сообщение поддерживает любое количество кнопок. Кнопки можно добавлять, дублировать, удалять и переставлять.

Действие кнопки:

- продолжить по собственной ветке;
- открыть внешнюю ссылку;
- перейти к оплате продукта.

У каждой ветвящей кнопки есть стабильный внутренний ID и отдельный порт на графе. Переименование кнопки не ломает стрелку. При удалении связанной кнопки редактор запрашивает подтверждение и удаляет только её переход.

Основная навигация:

- Схема;
- Тесты;
- Медиа;
- Продукты;
- Бот;
- Статистика.

На схеме используется единое контекстное управление без переключателей:

- протягивание по пустому полю перемещает весь холст;
- протягивание по блоку перемещает сам блок;
- одиночный клик по пустому полю подготавливает выделение, а следующее протягивание по полю рисует рамку;
- повторный обычный клик, выбор блока или `Esc` отменяет подготовленное выделение.

Масштабирование колёсиком, жестом и кнопками работает всегда. Мини-карта не используется.

Переменные, формулы, AST, универсальные условия, A/B-распределение, подворонки, комментарии, группы и технические ключи удалены из формата и обычного интерфейса.

## Тесты и scoring

Психологические тесты не упрощены по возможностям:

- несколько тестов в одной воронке;
- вопросы типов «один вариант», «несколько вариантов», «числовая шкала», «число» и «свободный текст»;
- включение, порядок, дублирование и перемешивание вопросов и ответов;
- произвольные шкалы с названием и цветом;
- визуальная таблица баллов «ответ × шкала»;
- динамический максимум только по активным вопросам;
- нормализация в проценты;
- главный и дополнительный результат;
- комбинированный результат при близости процентов;
- настраиваемый порог близости;
- детерминированный расчёт;
- ручное проверочное прохождение с объяснением результата.

Основные и комбинированные результаты хранят название, короткий и полный тексты, рекомендации, материал и кнопки после результата.

## Бот и отслеживаемые ссылки

Вкладка «Бот» содержит:

- отображаемое название и username будущего бота;
- часовой пояс и срок неактивной сессии;
- тихие часы;
- поведение повторного входа;
- команду и текст отписки;
- общие ограничения напоминаний;
- ссылки и источники.

Для отслеживаемой ссылки задаются название, источник, кампания и необязательная метка контента. Безопасный уникальный код создаётся автоматически и остаётся стабильным. Если указан username, редактор показывает готовую deep link:

```text
https://t.me/username_bot?start=instagram_test_july
```

Будущий исполнитель сможет сохранить код источника в сессии и связать с ним начало, завершение, результат теста, заявку и оплату.

## Статистика

Редактор отображает только снимок, записанный в `.funnel` внешним исполнителем:

- обзор;
- этапы и отвал;
- вопросы теста;
- результаты;
- источники;
- продукты и оплаты;
- контакты и заявки с экспортом CSV.

Если для созданной ссылки данных нет, интерфейс честно сообщает, что статистика появится после запуска Telegram-бота и импорта обновлённого файла.

## Формат `.funnel` 2.0.0

Новый major-формат содержит только:

```text
project / funnel / bot / nodes / edges
tests / assets / products / analytics / editor
```

Исполняемые данные отделены от координат редактора. Все блоки, кнопки, результаты, материалы, продукты и ссылки имеют стабильные ID. Импорт проверяется через Zod; содержимое файла не выполняется как JavaScript. В проекте нет `eval` и `new Function`.

Формат `1.x` — старая расширенная архитектура — намеренно несовместим. При импорте такого файла показывается сообщение:

> Этот файл создан в старой расширенной версии конструктора и не поддерживается новым упрощённым форматом.

Старые локальные записи не удаляются из IndexedDB, но новый интерфейс их не открывает. Для нового формата поддерживается цикл экспорт → импорт → редактирование → экспорт без потери веток, scoring, статистики и координат.

Создание следующей версии копирует сценарий и сбрасывает только снимок статистики после подтверждения. Исходная версия не изменяется.

Архитектурное решение: [`docs/ADR-002-simplified-funnel-2.0.md`](docs/ADR-002-simplified-funnel-2.0.md). Сценарий ручной проверки: [`docs/WORKFLOW.md`](docs/WORKFLOW.md).

## Осознанные ограничения

- Telegram-бот и серверное хранение не реализованы.
- Bot API token не вводится и не хранится.
- Реальная ЮKassa не подключена.
- Файлы медиа не встраиваются в `.funnel`; сохраняется только логическая ссылка.
- Статистика не собирается в реальном времени.
- QR-код отслеживаемой ссылки пока не генерируется.

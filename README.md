# Воронка — автономный конструктор Telegram-воронок

Полноценный статический редактор сценариев будущего Telegram-бота. Он работает без backend, аккаунта и сети: структура, настройки и снимок статистики переносятся одним читаемым UTF-8 JSON-файлом с расширением `.funnel`.

Важно: приложение не подключено к Telegram, ЮKassa, облачному хранилищу или живой аналитике. Платежи, отправка сообщений, медиа и внешние переходы в симуляторе только моделируются; токены и секреты в проект не вводятся.

## Запуск

Требуется Node.js 20 или новее.

```bash
npm install
npm run dev
```

Проверка production-версии:

```bash
npm test
npm run build
npm run preview
```

## Что реализовано

- визуальная схема на `@xyflow/react`: 22 типа блоков, категории и поиск, drag-and-drop, множественное выделение, групповой перенос, копирование, вставка, дублирование, выравнивание, автолэйаут, сворачивание карточек, mini-map и подсветка пути;
- отдельные разделы переменных, тестов и результатов, медиа, продуктов, настроек, проверки, статистики, сравнения и ревизий;
- безопасные условия с вложенными `И / ИЛИ / НЕ`, типизированными операторами и обязательной веткой «Иначе»;
- типизированные переменные, безопасные шаблоны `{{key | default: "значение"}}`, действия над значениями и формулы в виде AST без `eval`;
- тесты с произвольными вопросами и шкалами, scoring, динамическими максимумами, нормализацией, детерминированными ничьими, одиночными и комбинированными результатами;
- реестр логических медиа, включая голосовые, видеокружки и ограничения будущих файлов; бинарные данные в `.funnel` не попадают;
- каталог продуктов и все будущие исходы оплаты без реального обращения к провайдеру;
- сессии, повторный вход, таймеры, ожидание даты, напоминания, часовые пояса, тихие часы, источники и отписка;
- общий детерминированный симулятор с виртуальным временем, тестовыми сценариями, переменными, scoring, журналом переходов и проверкой ожидаемого результата;
- доменная валидация по девяти разделам с ошибками, предупреждениями, советами, безопасными автоисправлениями и текстовым отчётом;
- расширенная снимочная аналитика: этапы, связи, тесты, результаты, продукты, источники, контакты и заявки; таблицы имеют поиск, пагинацию и CSV с UTF-8 BOM;
- версии с независимой статистикой, ID-based diff структуры и аналитических дельт, локальные ревизии в IndexedDB;
- миграция `0.1.0 → 1.0.0`, сохранение стабильных ID и неизвестных полей, изоляция повреждённой аналитики;
- адаптивная работа на телефоне и планшете, локальное автосохранение, undo/redo и предупреждение о несохранённых изменениях.

Расширенный пример: [`public/demo-7-mehanizmov-v1.funnel`](public/demo-7-mehanizmov-v1.funnel). Fixture принятого MVP: [`public/fixtures/demo-diagnostika-v0.1.funnel`](public/fixtures/demo-diagnostika-v0.1.funnel).

## Формат `.funnel` 1.0.0

Один файл содержит одну воронку одной версии. Основные корневые разделы:

```text
project / funnel / settings / variables / nodes / edges
tests / resultSets / assets / products / testScenarios
analytics / editor
```

Исполняемые данные отделены от визуальных: координаты и состояние полотна находятся в `editor`, а не определяют поведение сценария. Связи используют стабильные `id`; переименование или перестановка вариантов не ломает переходы.

Импорт сначала проходит Zod-проверку структуры, затем доменную проверку. Поддерживается только известная major-версия. Совместимые неизвестные поля сохраняются при round-trip. Никакой текст или выражение из импортированного файла не выполняется как JavaScript.

Снимок `analytics` относится к конкретному `funnel.version`. Экспорт текущей версии сохраняет его, создание следующей версии копирует сценарий, увеличивает номер и начинает со статистики с нуля. Исходный документ не изменяется.

Подробности решений: [`docs/ADR-001-funnel-1.0.md`](docs/ADR-001-funnel-1.0.md). Рабочий сценарий проверки: [`docs/WORKFLOW.md`](docs/WORKFLOW.md).

## Локальные данные

Черновики и до 20 ревизий каждой версии хранятся в IndexedDB текущего браузера. Это не серверная резервная копия и не синхронизация между устройствами. Для переноса используйте экспорт `.funnel`.

## Горячие клавиши схемы

- `⌘/Ctrl + Z` — отменить;
- `⇧ + ⌘/Ctrl + Z` — повторить;
- `⌘/Ctrl + C`, `⌘/Ctrl + V` — копировать и вставить выбранные блоки;
- `⌘/Ctrl + D` — дублировать;
- `Delete` / `Backspace` — удалить после подтверждения;
- `Shift`, `⌘` или `Ctrl` + клик — множественное выделение.

## Публикация на GitHub Pages

Vite использует относительный `base`, а маршрутизация — `HashRouter`, поэтому сборка работает в подпапке Pages. Workflow `.github/workflows/deploy-pages.yml` устанавливает зависимости, выполняет тесты, собирает и публикует `dist`.

1. Отправьте проект в ветку `main` GitHub-репозитория.
2. В **Settings → Pages → Build and deployment** выберите **GitHub Actions**.
3. Запустите workflow или отправьте следующий commit.

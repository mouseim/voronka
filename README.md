# Воронка — автономный конструктор Telegram-воронок

Рабочий MVP визуального конструктора из ТЗ. Приложение полностью статическое: без backend, авторизации, базы на сервере и подключения к Telegram. Проекты переносятся в виде читаемых UTF-8 JSON-файлов с расширением `.funnel`.

## Запуск

Требуется Node.js 20 или новее.

```bash
npm install
npm run dev
```

Production-сборка и тесты:

```bash
npm test
npm run build
npm run preview
```

## Что реализовано

- стартовый экран, импорт кликом и drag-and-drop, несколько локальных черновиков в IndexedDB;
- визуальный граф на `@xyflow/react`: добавление кликом и перетаскиванием, движение, соединение, удаление, zoom/pan, mini-map и fit view;
- все семь MVP-блоков: старт, сообщение, выбор, вопрос, задержка, медиа и завершение;
- редактирование вариантов и произвольных шкал баллов со стабильными ID;
- undo/redo и автосохранение с индикатором состояния;
- полная проверка логики с переходом к проблемному блоку;
- реестр логических медиа-ссылок и все шесть ожидаемых типов файлов;
- интерактивный симулятор с отладочным режимом и накоплением баллов;
- отдельный адаптивный раздел статистики: сводка, этапы, связи, контакты и заявки;
- импорт/экспорт `.funnel`, сохранение совместимых неизвестных полей и понятные пути ошибок;
- экспорт новой версии с увеличением номера и чистой статистикой;
- демонстрационная воронка со всеми блоками и вымышленными данными;
- адаптивные панели редактора для мобильного экрана;
- тесты модели, round-trip, версий, графа, медиа и аналитики;
- GitHub Actions для проверки, сборки и публикации на GitHub Pages.

Готовый демонстрационный файл: [`public/demo-diagnostika-v1.funnel`](public/demo-diagnostika-v1.funnel).

## Формат и принятые решения

Текущая версия схемы — `0.1.0`. Переходы хранятся в отдельном массиве `edges`. Для кнопок выбора и ответов `sourceHandle` равен устойчивому ID варианта; это позволяет переименовывать и переставлять варианты без поломки связей. Блок `media` хранит только логическое требование к будущему файлу, а массив `assets` синхронизируется перед экспортом.

Zod проверяет безопасную структурную схему. Отдельный доменный валидатор проверяет обязательные поля, единственный старт, достижимость, существование концов связей, переходы вариантов, таймеры, `assetKey` и соответствие версии статистики. Никакой код из импортированного файла не выполняется.

Vite настроен с относительным `base: './'`, а навигация использует `HashRouter`, поэтому production-сборка работает в подпапке GitHub Pages.

## Публикация на GitHub Pages

1. Создайте GitHub-репозиторий и отправьте проект в ветку `main`.
2. В настройках репозитория откройте **Pages → Build and deployment**.
3. Выберите **GitHub Actions** как источник.
4. Workflow `.github/workflows/deploy-pages.yml` выполнит тесты, сборку и публикацию.

## Осознанно отложено

В соответствии с ТЗ не реализованы Telegram/VK-боты, backend, серверная БД, настоящая загрузка медиа, платежи, рассылки, облачные аккаунты, синхронизация устройств, живая статистика, сравнение версий и выполнение произвольных условий. PWA-кэш полного приложения также оставлен на следующий этап; уже открытый проект при потере сети продолжает работать, а изменения сохраняются в IndexedDB.

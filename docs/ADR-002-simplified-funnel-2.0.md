# ADR-002: упрощённый формат `.funnel` 2.0

Статус: принято  
Дата: 2026-07-23

## Контекст

Версия 1.0 совмещала визуальный конструктор и инструменты, похожие на среду программирования: переменные, формулы, AST, вложенные условия, A/B-ветки и технические параметры исполнения. Это повышало порог входа для основной аудитории.

## Решение

Создать несовместимую major-версию `2.0.0` и оставить только предметные сущности:

- 10 типов исполняемых блоков;
- ветвление через стабильные выходы кнопок и результатов теста;
- подробные психологические тесты;
- реестр логических медиа;
- продукты;
- понятные настройки будущего Telegram-бота;
- отслеживаемые deep links;
- снимочную аналитику;
- координаты визуального редактора.

Переменные, формулы, универсальные условия, A/B-распределение, подворонки и технические блоки не мигрируются.

## Связи кнопок

Видимый текст кнопки не является идентификатором связи. Кнопка получает стабильный `id`, который используется как `sourceHandle` стрелки. Переименование обновляет только подпись. Удаление кнопки удаляет переход с соответствующим `sourceHandle`.

Сообщение без ветвящих кнопок имеет один выход `next`. Если есть ветвящие кнопки, каждая формирует собственный выход.

## Scoring

Баллы хранятся декларативно в `answer.scores[scaleId]`. Максимум каждой шкалы вычисляется по активным вопросам:

- для одиночного ответа берётся максимальный положительный вклад вопроса;
- для множественного ответа суммируются возможные положительные вклады.

Процент равен `score / dynamicMaximum × 100`. Равенства разрешаются стабильным порядком шкал. Комбинированный результат выбирается только при попадании разницы в заданный порог и наличии соответствующего текста.

## Совместимость и безопасность

Импорт поддерживает только `2.0.0`. Файлы `1.x` отклоняются до разбора внутренних сущностей с понятным сообщением.

Импортированный JSON проверяется Zod-схемой. Ни один фрагмент `.funnel` не выполняется как код.

## Последствия

Положительные:

- существенно меньше терминов и экранов;
- ветвление видно непосредственно на схеме;
- модель проще валидировать и реализовывать в будущем Telegram-боте;
- тесты сохраняют полную диагностическую механику.

Отрицательные:

- старые расширенные файлы нельзя открыть в новом редакторе;
- сложные программируемые сценарии требуют отдельного инструмента или будущего расширения формата.
